# 任务计划：开发约定与技术栈选型

- 日期：2026-10-11（Asia/Taipei）
- 任务类型：文档
- 背景：用户确认将本次讨论的小 MVP 流程及技术栈约定写入仓库。

## 目标

明确独立应用 Monorepo 的技术栈与职责边界，并规定每个独立任务在 `changes/` 中先记录计划、持续更新结果 checklist，便于后续回溯。

## 范围

### 本次包含

- 保留现有应用隔离与独立交付规则，明确前端 TypeScript、后端 Go。
- 明确 TanStack Query、Zustand、Go + Gin + GORM + PostgreSQL + Redis + Asynq 的选型及使用边界。
- 在 AGENTS.md 中定义小 MVP 流程、任务目录粒度、计划与结果字段及完成标准。
- 新增技术栈选型文档，同步 PRD 中已过时的技术表述，并增加文档入口。
- 为新技术栈文档设置精准的 Git 忽略例外，保留其他本地文档的忽略策略。

### 本次不包含

- 安装依赖、修改锁文件、接入数据库/缓存/任务队列、实现业务代码或改动部署配置。
- 调整产品功能、权限模型、移动系统支持范围或应用商店发布范围。
- 引入跨应用共享代码、工作区耦合、微服务或 Kafka。
- 自动提交、暂存或推送 Git 变更。

## 已确认决策与待确认问题

- 按独立任务创建目录，同一目标的追问、实施与修复更新原目录，不按单条消息拆分。
- 讨论和文档任务也遵循记录流程；讨论交付物为决策与待确认问题，不伪造代码交付。
- plan.md 在实施前建立；result.md 同时建立并持续更新 checklist。
- 已选型不等于已接入；技术栈文档必须如实区分当前脚手架与目标能力。
- App 已选 React Native + Expo；支持的移动系统和可验收交付方式仍需后续确定。

# Skill 管理插件产品需求文档（PRD）

- **文档版本**：v0.1
- **更新日期**：2026-10-11
- **文档状态**：讨论稿 / 独立能力范围草案
- **产品定位**：插件化实现、独立入口的 Skill 资产管理能力
- **部署边界**：随单企业自托管 ERP 实例部署，复用平台认证、RBAC、审计与数据库
- **交付关系**：独立规划与验收，暂不扩大平台底座 MVP 的 P0 范围

> 已确认方向：Skill 管理虽然通过插件机制实现，但在产品上独立于插件中心。
> 本稿将 Skill 暂定义为供 AI / Agent 使用的可复用说明与操作规范，而非员工技能档案；该定义、具体格式及交付阶段仍需确认。
> “独立”指独立导航、页面、权限、数据模型和资产生命周期，不默认要求独立服务、独立部署或脱离 ERP 运行。

------------------------------------------------------------------------

## 1. 背景与目标

企业的业务处理规范、提示词及 Agent 操作说明容易散落在文档和个人工具中，难以发现、复用、追溯版本和控制使用范围。本能力将这些内容作为 Skill 资产集中管理，并为后续受控的 AI / 自动化消费提供公开契约。

### 1.1 产品目标

- 提供独立的 Skill 管理入口，不要求用户先进入插件中心。
- 支持 Skill 的创建、编辑、检索、版本发布、启停、归档及导入导出。
- 区分“管理插件”与“管理 Skill”，两者的权限与生命周期互不替代。
- Skill 不绑定某个业务插件；业务插件停用后仍可管理其相关 Skill 内容。
- 在无模型服务、无 AI 执行插件和无外网时，仍能完成资产管理。

### 1.2 非目标

- 首版不交付 Agent 执行器、模型供应商管理、对话产品或自动业务写入。
- 不建设在线 Skill 市场、交易结算、云端同步或厂商托管平台。
- 不扫描用户电脑目录，不自动修改本地 AI 工具的 Skill 文件。
- 不执行导入内容中的脚本、SQL、命令或任意插件代码。
- 不将 Skill 当成插件安装包，也不在平台核心硬编码业务 Skill。

## 2. 独立性与系统边界

### 2.1 三类对象

| 对象 | 职责 | 管理位置 |
| --- | --- | --- |
| 平台核心 | 认证、成员、角色权限、插件注册与启停、审计、部署维护 | 平台设置 / 插件中心 |
| Skill 管理插件 | Skill 存储、检索、编辑、版本与资产状态管理 | 独立“Skill 管理”入口 |
| 单个 Skill | 可复用的说明内容、元数据、版本及使用约束 | Skill 列表与详情 |

**一个 Skill 不是一个 ERP 插件。** 创建、导入、发布或启用 Skill 不会注册新插件、运行迁移或加载代码。

### 2.2 独立产品入口

- Skill 管理插件已启用且用户有查看权限时，Web 主导航显示一级“Skill 管理”入口。
- 列表、编辑、版本与归档页面均在该入口内完成，不嵌套在插件中心详情页中。
- 插件中心只显示 Skill 管理插件自身的版本、兼容性、启停状态与权限声明，不管理单个 Skill。
- 无插件管理权限但有 Skill 权限的成员，可直接访问 Skill 管理。
- 仅有插件管理权限的成员，不自动获得 Skill 内容的查看、编辑或发布权限。
- 插件自身停用后遵循平台规则：入口隐藏、资产 API 拒绝访问、数据保留；重新启用后恢复原资产状态与权限。

### 2.3 业务与执行解耦

- 首版只依赖平台公开契约，不强制依赖 CRM、商品、库存或 AI 执行插件。
- Skill 可声明所需能力及关联业务插件，但关联信息不赋予权限，也不调用插件内部实现。
- 业务插件停用不删除、归档或隐式停用 Skill；资产仍可查看和编辑。
- 后续消费方通过公开契约读取已发布的可用版本，不直接访问 Skill 数据表或内部服务。
- 消费方未实现、能力缺失或依赖插件停用时，只将对应消费标记为不可用，不影响资产管理。
- Skill 所需能力是需求声明，不是授权令牌；实际业务操作必须再次校验调用者身份、权限和目标插件状态。

## 3. 用户与权限

角色是建议配置，最终由权限项控制。首版采用实例内角色权限，不交付单个 Skill 的私有共享或资源级 ACL；拥有查看权限的成员可查看本实例所有 Skill，包括草稿和历史版本。

| 建议角色 | 能力 |
| --- | --- |
| Skill 查看人员 | 检索、查看详情和历史版本 |
| Skill 编辑人员 | 创建、编辑草稿、维护分类标签、导入 |
| Skill 发布人员 | 发布、启停、回退当前版本、归档与恢复 |
| Skill 导出人员 | 导出有权查看的资产，作为单独授予的能力 |
| 平台管理员 | 控制管理插件启停、分配上述权限；不默认获取全部内容权限 |

建议权限标识：

| 权限 | 用途 |
| --- | --- |
| `skills.read` | 查看列表、正文与版本 |
| `skills.write` | 新建、编辑草稿、删除从未发布的草稿 |
| `skills.import` | 导入资产；同时要求 `skills.write` |
| `skills.publish` | 发布新版本、切换当前版本；同时要求 `skills.read` |
| `skills.manage` | 启停、归档、恢复；同时要求 `skills.read` |
| `skills.export` | 导出资产；同时要求 `skills.read` |

服务端逐请求验证认证、成员状态、管理插件状态及所需权限；隐藏按钮不是授权措施。权限被撤销后，旧页面与旧会话的后续请求也必须被拒绝。权限标识以最终平台契约为准。

## 4. 首版范围与优先级

本节 P0 / P1 仅针对 **Skill 管理自身首版**，不等于 ERP 平台底座 MVP 的优先级。

| 编号 | 优先级 | 需求 | 核心验收 |
| --- | --- | --- | --- |
| SK-01 | P0 | 独立导航与权限 | 有 Skill 权限且无插件管理权限的成员可直接进入 |
| SK-02 | P0 | 创建与编辑草稿 | 校验必填项与唯一标识，未保存变更有提醒 |
| SK-03 | P0 | 列表与检索 | 名称 / 标识 / 描述搜索，分类 / 标签 / 状态筛选，分页 |
| SK-04 | P0 | 详情与安全预览 | 显示正文、元数据、状态、版本和修改人；预览不执行内容 |
| SK-05 | P0 | 发布与版本管理 | 发布快照不可覆盖，编辑只改草稿，支持切换历史发布版本 |
| SK-06 | P0 | 启停与归档 | 停用不丢失内容，归档后不可消费，恢复默认停用 |
| SK-07 | P0 | 导入导出 | 文件校验、预览、冲突处理、失败无半条资产、导出不带权限或凭证 |
| SK-08 | P0 | 审计与恢复 | 关键动作留痕，备份恢复包含正文、版本与状态 |
| SK-09 | P1 | 版本差异对比 | 按元数据与正文展示差异 |
| SK-10 | P1 | 模板与批量操作 | 模板创建，批量启停 / 归档逐条反馈结果 |
| SK-11 | 后续 | 执行 / 消费集成 | 在独立消费方 PRD 中定义，不以模拟执行替代真实结果 |
| SK-12 | 后续 | App、资源级权限、外部工具同步 | 经场景验证后分别规划 |

## 5. Skill 内容与数据模型

### 5.1 元数据与正文

- 系统 ID：服务端生成，不受导入文件控制。
- Skill 标识：实例内唯一、创建后不可变，用于稳定引用；具体命名校验规则在设计阶段确定。
- 名称、简短描述：必填，名称可重复，但标识不可重复。
- 分类：首版使用预设值（通用、业务规范、数据处理、其他），不单独建设分类管理器。
- 标签：可选的文本集合，用于检索与筛选。
- Markdown 正文：必填，用于目的、适用场景、操作步骤、输入输出要求及限制说明；章节模板为辅助，不强制解析成可执行流程。
- 所需能力 / 关联插件标识：可选，仅作依赖与消费提示，不构成代码入口或权限授予。
- 来源信息：手工创建或文件导入、来源说明；不默认抓取来源 URL。
- 创建人、修改人及时间：服务端根据会话生成。

不在正文或元数据中保存 API Key、密码和访问令牌。后续需要凭证时只能引用独立凭证管理能力，不能通过 Skill 导出泄露。

### 5.2 逻辑数据对象

| 对象 | 关键字段与职责 |
| --- | --- |
| `Skill` | 系统 ID、唯一标识、生命周期状态、启用状态、当前发布版本引用、审计时间 |
| `SkillDraft` | 可编辑元数据与正文、编辑修订号，每个 Skill 最多一个当前草稿 |
| `SkillVersion` | Skill ID、递增版本序号、不可变内容快照、发布说明、发布人、发布时间 |

- Skill 管理插件拥有上述数据及迁移，不直接写业务插件的数据表。
- 分类、标签、正文和关联能力随版本快照保存，消费方不得将新草稿与旧发布正文混合读取。
- 两人同时编辑时使用修订号检查；过期保存返回冲突并保留用户未提交内容，不静默覆盖。
- 发布、版本指针与审计记录应保持一致；失败不得出现“显示已发布但版本不存在”。
- 按实例保存，不新增同实例多企业模型；备份包括所有草稿、发布快照、状态和版本引用。

## 6. 生命周期与版本规则

生命周期与启用状态分开表达，避免“已发布”被误认为“正在执行”。

| 状态 | 编辑 | 发布 / 切换版本 | 能否启用 | 消费行为 |
| --- | --- | --- | --- | --- |
| 草稿（从未发布） | 可编辑 | 可首次发布 | 否 | 不提供给消费方 |
| 已发布 | 可维护独立草稿 | 可发布新版本或切换历史版本 | 是 | 仅启用时提供当前发布版本 |
| 已归档 | 只读 | 恢复后处理 | 否 | 拒绝消费 |

- 首次发布创建版本 1，资产默认停用；发布不自动授予权限或触发执行。
- 后续发布要求填写发布说明，并确认切换当前发布版本；若资产已启用，提示后续消费将使用新版本，保留原启用状态。
- 发布后的编辑只更新草稿，当前版本不变。发布新版本时生成递增快照，不覆盖历史内容。
- 回退通过切换到既有发布版本完成，不改写历史、不重置版本序号；有未发布草稿时提示并保留该草稿。
- 启用要求存在当前发布版本且未归档；停用只阻止消费，不影响查看、编辑和导出。
- 归档需确认影响，自动停用并保留草稿、历史与当前版本引用；默认列表排除归档资产，可在归档页查询。
- 恢复回到归档前生命周期，但保持停用，须再次明确启用。
- 首版只允许删除从未发布的草稿，需确认并审计；曾发布资产只能归档，不提供永久删除。
- 管理插件整体停用与单个 Skill 停用不同。整体停用保留单个资产状态，重新启用前提示原已启用 Skill 将恢复可消费条件。

## 7. 导入与导出

### 7.1 首版导入

- 支持单个 `.md` 文件（包括名为 `SKILL.md` 的文件），作为正文导入；名称、标识等由用户在预览中填写。
- 支持本系统导出的带格式版本号的 JSON 单资产文件，包含元数据及指定版本正文。
- 首版不支持 ZIP、目录批量上传、可执行附件或远程 URL 自动拉取；不承诺完整兼容外部工具的 Skill 包结构。
- 建议单文件大小上限 1 MiB，限制可配置，前后端均校验；确认前检查编码、扩展名、内容结构与必填项。
- 导入前显示正文预览、来源及冲突提示，解析文件不触发安装、发布、启用或执行。
- 标识冲突时，可选择修改标识创建新资产，或将内容写入既有资产草稿；更新草稿必须确认，且不得覆盖发布快照或改变启用状态。
- 导入新资产默认草稿、停用，操作人由当前会话确定；忽略文件中的系统 ID、权限、启用状态、版本指针和审计身份。
- 解析、校验或保存失败时不留下部分资产；已有草稿修订冲突时中止并提示重新预览。

### 7.2 首版导出

- 用户明确选择导出草稿或某个发布版本；不得默认把未发布内容当成当前发布版本导出。
- 支持正文 `.md` 与本系统 JSON 单资产文件；JSON 包含格式版本、Skill 标识、元数据、正文及来源版本说明。
- 不包含成员、角色、权限、系统内部 ID、审计明细、启用状态或凭证。
- 导出内容仅作为可移植资产，重新导入后需要重新发布和启用，不恢复访问授权。
- 文件格式为本系统契约草案，最终 schema、校验规则与外部格式兼容性单独确认，不宣称为通用行业标准。

## 8. 信息架构与交互

### 8.1 Web 页面

- **Skill 列表**：搜索、分类 / 标签 / 生命周期 / 启用状态筛选、分页、创建、导入与归档入口。
- **Skill 详情**：概览、当前发布正文、草稿提示、版本历史、来源及消费依赖提示。
- **草稿编辑**：元数据表单、Markdown 编辑 / 安全预览、保存、发布；显示待保存和修订冲突状态。
- **发布确认**：发布说明、将切换的版本、已启用资产的影响提示。
- **版本历史**：版本号、发布说明、发布人和时间，查看或切换历史版本。
- **归档列表**：查看归档资产及恢复；不提供消费入口。
- **导入 / 导出**：文件校验、预览、冲突处理、版本选择与明确结果反馈。

### 8.2 交互约束

- 无权限、管理插件停用、无数据、无搜索结果、请求失败分别展示，不混为“列表为空”。
- 不将网络失败或校验失败显示为保存、发布或导入成功。
- 离开未保存的编辑页面前提醒；修订冲突不丢弃当前输入。
- 发布 / 切换版本 / 归档 / 删除需明确确认；禁用操作说明原因。
- 无消费方时展示“资产已管理，尚未接入执行能力”，不提供虚假的运行按钮或运行记录。
- 首版只交付 Web 管理；App 不自动增加入口，不复制完整后台。

## 9. 关键流程

### 9.1 创建与发布

1. 编辑人员进入独立入口，新建并保存 Skill 草稿。
2. 发布人员检查元数据和正文，填写发布说明，确认发布。
3. 服务端生成不可变快照，首次发布后保持停用。
4. 管理人员明确启用；若尚无消费方，只表示资产可被授权消费，不产生执行任务。
5. 后续编辑保存草稿，不影响已发布内容；再次发布才切换版本。

### 9.2 业务插件停用

1. 某 Skill 声明了商品插件能力，商品插件被停用。
2. Skill 仍可在独立入口查看、编辑、发布、导出，不被级联删除或归档。
3. 详情提示相关消费能力不可用；未来消费方必须拒绝调用停用的商品能力。
4. 商品插件重新启用后，消费方重新检查兼容性与授权，不恢复被撤销的权限。

### 9.3 管理插件停用与恢复

1. 平台管理员在插件中心停用 Skill 管理插件，确认入口和资产 API 将不可用。
2. 后端拒绝旧会话及直接 API 请求，不删除任何 Skill 资产。
3. 管理员重新启用，确认保留状态的影响；导航根据用户权限恢复。
4. 原草稿、发布快照、归档状态及启用状态保持一致，可继续维护。

## 10. 技术与安全约束

- 遵循模块化单体与静态注册方向，管理插件随宿主 / 客户端构建，不交付在线热加载。
- `apps/web` 负责平台入口组合；模块专属界面隔离在插件 Web 目录中；后端领域逻辑在 `apps/api`，HTTP 传输层位于 `internal/transport`。
- 共享包不得反向导入应用代码；与业务插件及后续消费方只通过公开平台 / 模块契约协作。
- 实现阶段同步 OpenAPI 与 API 客户端；本 PRD 不直接新增接口代码。
- Markdown 预览禁用原始 HTML 和可执行嵌入，过滤危险链接；导入内容视为不可信数据，不能修改权限、系统配置或发布策略。
- 无外网时可管理、导入导出本地文件；可选外部消费方失败不得阻断资产 CRUD。
- 审计包含创建、草稿更新、删除、导入、导出、发布、版本切换、启停、归档与恢复的操作人、资源、版本、时间和结果。
- 日志及审计不默认保存完整正文、上传文件或敏感凭证；关键状态变更与审计一致，不能无记录成功。
- 后续执行集成必须另行定义提示注入防护、工具白名单、业务写入确认和执行审计；本管理插件不承担安全执行器职责。

## 11. 首版验收清单

- [ ] 有 `skills.read` 而无插件管理权限的成员可从一级导航查看 Skill，不能启停管理插件。
- [ ] 仅有插件管理权限的成员不能通过直接 API 读取或修改 Skill 正文。
- [ ] Skill 管理不依赖任何正式业务插件、模型账号或执行器；断网仍可完成资产管理。
- [ ] 创建 / 导入单个 Skill 不增加插件登记，不执行代码；导入文件不能伪造操作人或授予权限。
- [ ] 草稿修改不改变当前发布版本；历史版本不可被普通编辑或导入覆盖。
- [ ] 启用无发布版本的资产被拒绝；停用、归档和恢复符合状态规则。
- [ ] 发布和历史版本切换有确认及审计，失败后版本引用与状态无部分更新。
- [ ] 并发草稿保存产生可处理的冲突，不静默覆盖；失败页面保留用户输入。
- [ ] 名称 / 标识 / 描述检索、筛选、分页与归档视图正确区分空结果和请求失败。
- [ ] 非法文件、超限文件、恶意 HTML / 链接及标识冲突得到明确处理，不产生执行或越权。
- [ ] 导出指定版本再导入，可恢复对应元数据与正文，但仍为草稿、停用且不带原授权。
- [ ] 关联业务插件停用后 Skill 仍可管理；管理插件停用后旧会话的资产请求被拒绝。
- [ ] 管理插件重启、重新启用及数据库备份恢复后，内容、版本引用、状态和权限保持一致。
- [ ] 权限撤销后的后续请求被拒绝，日志 / 审计不泄露正文或凭证。

## 12. 交付阶段

1. **范围确认**：确认 Skill 定义、独立入口、角色权限及交付排期。
2. **资产管理首版**：交付本稿 P0，独立验收，不以 AI 执行作为完成条件。
3. **易用性增强**：按真实需求增加差异对比、模板与批量操作。
4. **受控消费**：另写消费方 / 执行插件 PRD，明确版本固定、依赖检查、实际业务授权和风险确认。
5. **生态兼容**：验证具体外部工具格式、目录包、同步与资源级权限后再扩展。
